# MoFox Bot 人际关系一体化方案

> 目标：打通群/私聊/跨群的人际关系与上下文感知，降低“割裂感”，让同一用户在不同场景下保持连续的记忆、情感与角色一致性，同时兼顾性能与隐私。

## 现状痛点
- 群内割裂：只看当前群的上下文或印象，缺乏跨群聚合。
- 群与群割裂：同一用户在不同群的行为与情感未统一，容易出现“认不出人”。
- 群与私聊割裂：私聊与群聊记忆不共享，情感/亲密度难以延续。
- 上下文缺失：未命中当前会话的最近记忆时，回退策略弱，导致“不认识”。

## 整体思路
1) 建立“全局身份 + 场景视图”的关系图谱：
   - 全局节点：以跨平台用户 ID 作为主键（QQ:uin）。
   - 场景视图：按群/私聊/跨群行为生成局部视图，写入同一全局节点的不同 facet。 
2) 双轨记忆融合：
   - 短期：会话记忆（chat memory）按会话窗口缓存。
   - 长期：关系图谱/兴趣值/亲密度在 Memory Graph 中维护，跨场景共享。
3) 关联检索策略：
   - 查询时先以全局用户节点为入口，融合“当前场景权重 + 全局近期权重 + 亲密度/兴趣度”排序。
   - 缺失上下文时，回退到全局节点的最近互动和高亲密度边，而不是返回“不认识”。
4) 一致的更新策略：所有互动都写入同一全局节点，并在 facet 中标记来源场景（群号/私聊）。

## 数据模型（建议落地）
- 节点：User(uin, platform, profile, 最近活跃时间, 全局亲密度 baseline)。
- Facet：SceneFacet(scene_id, scene_type=group|private, 最近互动向量/关键词、局部亲密度、情感分布、兴趣主题 Top-N)。
- 边：
  - User-SceneFacet（所属关系）。
  - User-User（关系/亲密度/共现频次，来源：同群互动、@、互相回复）。
  - User-Topic（兴趣主题节点，来源：主题提取）。

## 写入流程
1) 解析消息 → 统一身份键（uin）。
2) 获取或创建 User 节点，获取对应 SceneFacet（群号/私聊）
3) 更新：
   - 局部：facet 的亲密度、情感计数、关键词向量（轻量 TF-IDF 或 embedding）。
   - 全局：User 节点的亲密度 baseline（衰减 + 增量），兴趣主题计数。
   - 边：User-User 共现（同一会话窗口的互动），User-Topic 计数。
4) 写入队列：通过 `AdaptiveBatchScheduler` 异步批量落库，避免逐条 I/O。

## 读取/检索策略（回复时）
1) 入口：uin + 当前 scene_id。
2) 聚合候选：
   - 场景优先：当前 SceneFacet 最近 N 次互动。
   - 全局补充：User 节点的最近全局互动、高亲密度关系、高权重主题。
3) 评分排序：
   - `score = w_scene * recency_scene + w_global * recency_global + w_affinity * intimacy + w_interest * topic_match`
   - 无匹配时，回退到全局最近互动的摘要，而不是空。
4) 输出组装：
   - 关系标签（如“老朋友”“常在某群互动”）。
   - 兴趣提示（最近聊过的主题）。
   - 亲密度/情感语气调节参数，影响回复语气。

## 系统改动建议（结合现有架构）
- 数据层：
  - 新建 `relationship_facet`、`user_topic_edge` 等模型，统一走 `CRUDBase`/`QueryBuilder`。
  - 写入用 `AdaptiveBatchScheduler`，避免循环单条 insert。
- 记忆层：
  - 在 `memory_graph` 中增加 facet 概念，保持一份全局节点，多个场景视图。
  - Chat memory 命中失败时，回退调用 Memory Graph 聚合接口。
- API 层：
  - 封装 `get_user_profile(uin, scene_id)`：返回组合后的关系快照（场景 + 全局）。
  - 封装 `update_relationship(uin, scene_id, interaction)`：写入统一队列。
- 事件/调度：
  - 在消息处理链路中插入轻量更新（不阻塞主流程）；重计算任务由 `unified_scheduler` 定时异步执行（如亲密度衰减、主题重排）。
- 缓存：
  - L1 内存缓存最近访问的 user snapshot；L2 SQLite（WAL）局部预取；L3 预加载热门活跃用户。

## 算法与策略细节
- 亲密度更新：`intimacy = decay(intimacy, t) + k1*直接互动 + k2*@/回复 + k3*私聊权重`。
- 主题抽取：
  - 短文本：关键词 + 轻量 embedding 聚类。
  - 可用现有 LLM 工具接口提炼 Top-N 话题，写入 User-Topic 边。
- 回退策略：
  - 无当前场景记录 → 用全局最近互动摘要。
  - 无全局记录 → 以“首次见面”模板回复，顺带请求自我介绍，写入新节点。

## 隐私与可控性
- 为用户提供“清除关系记忆”或“重置亲密度”接口（命令或管理面板）。
- 对跨群信息展示做最小化：仅用作内部语气/策略，不在群里暴露其他群的信息。
- 审计日志：记录何时从全局记忆调用了跨场景信息。

## 落地路线图
1) 数据层与模型落库（facet + 边），写入路径接入 `AdaptiveBatchScheduler`。
2) 封装 `get_user_profile`/`update_relationship` API，替换现有分散调用。
3) 回复链路：添加聚合检索与回退策略；无命中不再返回“不认识”。
4) 调度任务：每日/每周衰减亲密度，重算主题权重。
5) WebUI/调试：新增用户关系视图（全局 + 场景），便于验证聚合效果。
6) 灰度上线：先对小流量群启用，观察回复的一致性与性能。

## 验收指标（可量化）
- 认人失败率（出现“不认识”或错认）下降 80%。
- 跨场景连续性主观评分 ≥ 4/5（人工抽检）。
- 关系检索 P95 延迟 < 50ms（命中缓存）/< 200ms（落库）。
- 数据正确性：样本抽检的亲密度/主题是否符合近期互动。
